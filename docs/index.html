Compute v1.0.0 · Open-Source Release

Self-Hosted Firecracker MicroVM Sandboxes

Host your own lightning-fast microVM cloud on any Linux machine with /dev/kvm. Spin up hardware-isolated sandboxes in milliseconds, and effortlessly replicate, pause/resume, and snapshot environments from the Web Dashboard, CLI, or REST API.

Overview & Architecture

Compute is an open-source, self-hosted platform for orchestrating hardware-isolated Firecracker microVM sandboxes and ephemeral distributed jobs on your own Linux machines, home labs, or private bare-metal servers. Unlike container-only runners that share the host kernel, every Compute sandbox boots a dedicated Linux kernel and root filesystem inside KVM while maintaining sub-second startup times.

computedControl Plane

Central daemon serving the REST/WebSocket API, embedded React Web Dashboard, authentication/RBAC, microVM manager, and HTTP/DNS edge routing.

computeCLI & TUI

Single-binary developer CLI for creating sandboxes, SSH/exec streaming, 1-click cloning, state saving, template management, and distributed job runs.

compute-workerWorker Agent

Autonomous host agent that dials outbound to computed over WebSocket/mTLS with zero inbound ports required on remote worker hosts.

Built for Self-Hosters Compute tracks real physical host utilization (allocated vCPUs, memory, disk, and saved states) rather than artificial cloud billing meters, giving you complete visibility and control over your hardware.

Self-Hosting Quickstart

Compute runs on any Linux host (x86_64 or arm64) with hardware virtualization (/dev/kvm), cgroup v2, and Docker Engine 24+ (or directly on bare metal via systemd).

1. Verify Host Readiness & Prepare Kernel Modules

bash
./scripts/preflight.sh
sudo ./scripts/host-prepare.sh

2. Configure Environment (.env)

Copy .env.example to .env and configure your administrator credentials:

bash
cp .env.example .env
chmod 600 .env

3. Install Kernel & Build Rootfs Artifacts

bash
sudo ./scripts/build-kernel.sh ./data/images
sudo ./scripts/build-rootfs.sh ./data/images 1024

build-kernel.sh downloads the pinned, checksummed Firecracker vmlinux for your architecture. Both steps are idempotent, or run make build-images to do both at once.

4. Launch with Docker Compose

bash
docker compose up -d
curl -fsS http://127.0.0.1:18080/api/v1/health

Open http://127.0.0.1:18080/ in your browser to sign in to the Compute Web Dashboard.

Authentication & .env Configuration

Compute enforces session and bearer-token authentication out of the box (COMPUTE_AUTH_ENABLED=true). By default, public self-signup is disabled (COMPUTE_SIGNUP_ENABLED=false) and the administrator account is bootstrapped directly from your .env file on daemon startup.

Default Security Posture Unauthenticated visitors to the Web Dashboard are gated at #/login. When COMPUTE_SIGNUP_ENABLED=false, the public registration tab and POST /api/v1/auth/signup endpoint reject anonymous signups with 403 signup_disabled. Only authenticated administrators can provision additional users via the Access → Users tab or POST /api/v1/users.
Environment Variable Default Description
COMPUTE_AUTH_ENABLED true Enables authentication across REST API, WebSocket, and Web Dashboard endpoints.
COMPUTE_SIGNUP_ENABLED false Controls whether anonymous users can self-register at #/signup / POST /api/v1/auth/signup.
COMPUTE_ADMIN_USERNAME admin Username for the bootstrap administrator account seeded and synced on daemon startup.
COMPUTE_ADMIN_EMAIL admin@compute.local Email address for the bootstrap administrator account.
COMPUTE_ADMIN_PASSWORD (required in .env) Password synced to the bootstrap administrator account on startup (clears lockouts and rotates credentials in place).
COMPUTE_ADMIN_SECRET (optional) Static root bearer secret for automation; resolves to the bootstrap admin identity.
COMPUTE_BIND_ADDRESS 127.0.0.1 IP address the control plane listens on. Set 0.0.0.0 only after replacing the default admin credentials or behind a trusted reverse proxy.
COMPUTE_API_PORT 18080 TCP port for the control-plane API and embedded Web Dashboard.

Creating & Managing Sandboxes

Sandboxes are persistent Firecracker microVMs with dedicated ext4 root disks, private virtual NICs (TAP devices), and optional SSH/HTTP ingress routing. You can launch sandboxes from the Web Dashboard (New Sandbox) or via the compute CLI:

bash
# Create and start a 2 vCPU / 2 GB RAM sandbox
compute sandbox create --name dev-api --vcpus 2 --memory 2048 --disk-gb 20 --image ubuntu-24 --start

# Run interactive SSH or stream a command
compute sandbox ssh dev-api
compute sandbox exec dev-api -- docker ps

# Upload local project files into the sandbox
compute scp -r ./my-service dev-api:/root/my-service

Replicating (Cloning) Sandboxes

Compute makes replicating sandboxes effortless. Cloning copies the source sandbox's root filesystem and metadata into one or more independent sandboxes with optional spec overrides.

Web Dashboard: 1-Click Single & Multi-Replica Cloning

  • Click the Replicate (copy) button on any sandbox row or inside the Sandbox Inspector toolbar.
  • Set a Base Name and choose Replica Count (1–5) to spin up a single clone or a numbered fleet (e.g. worker-pool-1 .. worker-pool-5).
  • Optionally override vCPUs (1, 2, 4, 8, 16), Memory (MB), Disk (GB), Network Isolation (account vs isolated), and Start immediately after cloning.

REST API & CLI Replication

bash
# Clone via CLI
compute sandbox clone dev-api --name dev-api-staging

# Clone via REST API with resource & isolation overrides and auto-start
curl -X POST http://127.0.0.1:18080/api/v1/vms/dev-api/clone \
  -H "Authorization: Bearer $COMPUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "dev-api-canary",
    "vcpus": 4,
    "memory_mb": 4096,
    "disk_gb": 30,
    "network_isolated": true,
    "auto_start": true
  }'

Pausing & Resuming Sandbox State

Instead of shutting down a sandbox and losing in-memory processes, Compute lets you pause (save state) any running Firecracker microVM. Pausing serializes the guest's exact CPU registers, device state, and physical memory to disk (`vm.snap` + `vm.mem`) and releases host CPU/RAM capacity.

  • Web Dashboard: Click the Pause button on any running sandbox row or in the Inspector Drawer. The sandbox transitions to PAUSED (STATE SAVED). Click Resume to restore execution in milliseconds.
  • CLI & API: Use compute sandbox save-state <name> and compute sandbox resume <name>.
bash
# Freeze microVM memory + CPU state to disk
compute sandbox save-state dev-api

# Resume exactly where the sandbox left off
compute sandbox resume dev-api

Snapshots & Reusable Templates

Snapshots capture a point-in-time copy of a sandbox's disk image as a reusable template so you can pre-install compilers, models, or dependencies once and launch clean sandboxes from that checkpoint on demand.

  • From Any Sandbox Row or Inspector: Click the Snapshot camera icon, give the snapshot a name and description, and save.
  • From the Snapshots & Templates Page (#/snapshots): Click Create Snapshot to pick any source sandbox, or click Launch on any existing snapshot to spawn a new sandbox with customizable vCPUs, RAM, and auto-start.
bash
# Capture a reusable snapshot template from a sandbox
compute template create rust-toolchain --vm dev-api --desc "Rust 1.85 + cargo cache"

# Launch a new sandbox from the snapshot template
compute template launch rust-toolchain --name build-runner-01 --tier 4vcpu

Distributed Jobs & Workers

In addition to interactive sandboxes, Compute provides ephemeral Jobs (compute job run) that pack a local directory, stream it to an enrolled worker (or local control-plane runner), execute a command inside a fresh microVM, stream stdout/stderr back in real time, and destroy the VM upon completion.

bash
# Run an isolated build/test job with local file synchronization
compute job run --image ubuntu-24 --files ./ --cwd /workspace -- go test ./...

# Create an enrollment token for a remote compute-worker host
compute worker token create --name gpu-node-01

Networking, DNS & SSH

Compute configures a host bridge (default fcbr0 / 172.16.0.0/24) with per-sandbox TAP interfaces, anti-spoofing rules, and two selectable isolation modes:

  • account (default): Sandboxes owned by the same user/organization can communicate across the virtual bridge.
  • isolated: Strict per-sandbox iptables rules block lateral east-west traffic to other sandboxes.

See docs/dns-ssh.md and docs/domain-options.md for wildcard DNS and HTTPS edge proxy setup.

CLI Reference (compute)

Command Description
compute auth login / status / whoami Authenticate CLI against computed and inspect active credentials.
compute auth keys create / list / revoke Manage cmp_... API keys for CLI, CI, and SDK access.
compute sandbox create / list / inspect Provision and inspect Firecracker microVM sandboxes.
compute sandbox start / stop / delete Control sandbox power state and remove sandboxes.
compute sandbox clone <id> --name <new> Replicate an existing sandbox disk and configuration.
compute sandbox save-state / resume <id> Pause a running sandbox to disk and resume its saved memory/CPU state.

compute template create / list / launch / delete Create snapshots from sandboxes and launch new sandboxes from templates.
compute job run / list / logs / cancel Submit and monitor ephemeral distributed compute jobs.

REST API Reference

All control-plane endpoints are served under /api/v1 and accept either an HttpOnly session cookie (compute_session) or an Authorization: Bearer cmp_... header.

Method Endpoint Description
GET /api/v1/auth/status Public endpoint returning auth_enabled, signup_enabled, and admin_username.
POST /api/v1/auth/login Authenticate with username/email and password; sets session cookie and returns bearer token.
POST /api/v1/auth/signup Self-register a user account (returns 403 signup_disabled when closed unless called by an admin).
GET / POST /api/v1/users Admin-only: list all users or provision a new user (username, email, password, role).
DELETE /api/v1/users/{id} Admin-only: delete a user by ID or username and revoke their sessions/keys (guards self & bootstrap admin).
GET / POST /api/v1/vms List sandboxes or create a new Firecracker microVM sandbox.
POST /api/v1/vms/{id}/clone Replicate a sandbox with optional overrides (name, vcpus, memory_mb, disk_gb, network_isolated, auto_start).
POST /api/v1/vms/{id}/save-state Pause a running sandbox and serialize its Firecracker CPU/memory state to disk.
POST /api/v1/vms/{id}/resume Resume a paused sandbox from its saved memory/CPU state.
GET / POST /api/v1/templates List snapshots/templates or capture a new snapshot from vm_id.
POST /api/v1/templates/{id}/launch Launch a new sandbox from a snapshot template with optional spec overrides and auto_start.

Python & TypeScript SDKs

Official client libraries are included in sdk/python and sdk/typescript for programmatic sandbox orchestration, AI agent tool execution, and CI pipelines.

typescript
import { Sandbox } from "@compute-dev/sdk";

const sbx = await Sandbox.create({
  apiUrl: "http://127.0.0.1:18080",
  apiKey: process.env.COMPUTE_API_KEY,
  name: "agent-runner",
  vcpus: 2,
  memoryMb: 2048,
});

const res = await sbx.exec(["uname", "-a"]);
console.log(res.stdout);
